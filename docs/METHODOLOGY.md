# 整理方法

## 来源边界

下载索引只扫描 `sources.json` 白名单及其 include/exclude 目录。技能必须存在实际 `SKILL.md`，普通提示词、README 导航链接、插件说明不直接充当可安装技能。新来源通过独立 GitHub 搜索和集合 README 链接发现，按预算核实完整目录树和部分技能说明，再由维护者审核是否收录。未核实或尚未批准的候选保留在发现队列，不自动安装。来源使用 GitHub 的规范仓库地址；已知旧名记录于 aliases。检索范围与每轮证据见[发现报告](DISCOVERY.md)，操作见[维护说明](UPDATES.md)。

`sickn33/agentic-awesome-skills` 只扫描 `skills/`，避免把相同库的 Claude、Codex 等插件分发副本多次计入。每个来源解析 HEAD 对应的完整提交，目录与文件都来自同一固定版本。

## 三层关系

1. **完整目录一致：合并。** Git tree SHA 相同，说明文件名、内容、子目录和模式一致。优先保留发布者或专业来源为入口，其余位置保留为 aliases 和 locations。依次按来源 priority、完整路径稳定排序。优先级只控制入口，不表示官方认证或质量排名。
2. **说明正文一致、资源不同：关联，不合并。** 去除 frontmatter、规范化正文空白后计算 SHA-256。相同正文并不保证脚本或模板一致，仍是独立可下载条目。
3. **同名：版本组，不合并。** 名称相同但目录不同的技能全部保留。在 `data/duplicates.json` 的 same_name_families 中查找。近似功能和近似措辞也不自动合并，避免删除独立实现。

这是一种保守、可验证的去重方式，不是语义去重。它不会把“都能做 PDF”当作重复。

默认浏览另设用途分组与精选层：同名或说明相同的实现可以收在一个入口中，但不因此合并下载文件。同组代表会按查询和来源筛选变化；精选、核对、来源 Star 与退出记录的规则见[精选与退出](CURATION.md)。原始目录保持不变。

## 重新分类

根据名称和用途做可复现的关键词计分，名称权重高于描述，每项保留最多三个标签。AAS 主索引的上游分类映射到本项目主题并参与计分；科研、安全及发布者主题有明确的来源加权。第一标签作为主分类，其他标签支持交叉检索。中文搜索通过主题同义词扩展，描述保留上游语言。17 类中包含“其他与待细分”。

分类不是人工逐条审核，也不自动评判模型、技能优劣。要调整分类，可修改 `taxonomy.json`，然后用缓存重新生成：`python3 scripts/update.py --offline`。

## 文件和安装边界

下载的是固定 commit 下的整个技能目录，包含脚本、资源、示例和本地许可证。下载器同时携带祖先层级的授权告示，并写入 `.atlas-receipt.json` 记录版本、来源与字节数。它校验目录清单和每个 blob 的 Git 指纹，拒绝越界路径、符号链接、子模块及过大文件，不执行上游代码。

相对路径 `../`、插件根变量等只能作为依赖线索，不能完整描述依赖图。文件复制成功不等于客户端可用；外部包、服务、凭据、同级共享资源和插件运行环境仍以具体上游要求为准。下载完成后应在需要时阅读上游安装说明。

## 授权证据

保留技能 frontmatter 中的 license 原文、仓库级许可证线索、可用的上游告示。若没有技能级声明，标注待确认，不以仓库 MIT 或 Apache 标签代替完整授权判断。AAS 的代码和文字内容采用不同授权，因此另记内容许可线索，第三方例外仍按上游 notice 处理。公开可见、可下载、开源、可商用是不同事实，索引不混用。

## 更新和可复现性

每次生成记录各来源 commit，组合为 snapshot。网络失败不覆盖旧 catalog；最终一致性检查会重建所有 Git tree 指纹。缓存按 blob SHA 寻址，离线重建无需访问上游。已下载的技能不会自动改变；索引更新通过 PR 审核，保持变更可追踪。
