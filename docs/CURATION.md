# 精选 排序与退出规则

精选配置是 [curation.json](../curation.json)，默认上限 40 个用途。当前选择面向科研、文档图表、产品研究和开发任务，供人和 AI 先查；完整技能目录继续保留。

## 先查少量用途

命令行默认使用 `data/shortlist.json`，最多返回 5 个用途；精选未命中时扩展到全库。`show <ID>` 才输出完整详情，`show <ID> --alternatives` 用于比较同组实现。网页也默认精选，未命中时明确提示已扩展。

这是减少查找时无关输入和输出的方法，不表示精选覆盖了所有值得用的技能。

## 合并与排序

- 完全相同的完整目录继续按原有指纹规则去重。
- 同名、说明相同或明确人工关联的实现合成一个浏览入口，各自文件、许可、ID 和下载保持独立。人工跨名称关联必须写理由，同名本身不证明功能等价。
- 用途相关性优先；精确名称或完整 ID 可以命中所需实现。来源筛选和查询不会被精选首选版本覆盖。
- 同等相关性下，优先当前核对、下载验证或实际任务验证的记录，再参考精选入口、独立仓库和来源优先级。观察项降级；不让集合仓库的总 Star 挤掉更贴合任务的实现。
- 网页可以明确切换为来源仓库 Star 排序；这只是一种观察方式，不是质量评分。

## Star 与独立仓库

`scripts/refresh_signals.py` 读取白名单来源的 GitHub 仓库元数据，保存在 `data/repository-signals.json`。Star、采集时间、仓库归档状态分别记录；当前独立技能仓库指该非集合来源扫描到一个主技能，多个主技能的发布者或专业来源标为专题技能集。

高关注阈值默认为 10,000 Star，可以在 policy 中调整。超过 30 天的 Star 快照标为旧数据，不再作为高关注排序依据。获取失败保留原数值和原采集时间，首次缺失显示未知，不补零或伪造新时间。

Star 属于仓库；一个有许多技能的仓库，其 Star 不能分别当作每个技能的认可。独立仓库标记也不构成质量认证。

## 核对与复查

核对记录绑定完整条目 ID、commit 和目录指纹，分为用途与结构已核对、下载已验证、任务已跑通。上游版本或指纹变化时，旧记录转为待复核，不能继续当作当前版本验证。

默认精选复查期 30 天。候选必须给出进入日期或下次复查日期，默认观察期 30 天。复查到期进入观察并退出精选；这代表需要复核，不等于技能失效。缺少当前核对记录的精选也进入观察。

沿用已有每周更新流程刷新复查基准，变化通过 PR 呈现。`data/curated.json` 保存本次复查基准日；CI 按同一天重建，避免仅因跨天造成不可重复的页面差异。

## 归档与恢复

`lifecycle` 可显式指定 featured、candidate、watch、archived。观察或归档必须写原因；归档须记录日期，有替代项时用原始 ID 指向替代入口。

首次将 Composio 集合中的四个文档候选转入备选归档，分别指向当前核对过的 PDF、Word、PPT 和表格入口。它们的说明和文件并不完全相同，因此保留原始条目；不是声称旧版本无效，也不覆盖任何已下载文件。

归档默认退出搜索，可在“观察与归档”、包含归档筛选、`search --scope archived` 或原 ID 的 `show` 中查看。明确指定原 ID 仍可下载。没有新提交、Star 下降、仓库归档或没有聊天反馈，都不会单独触发淘汰。

恢复时更新核对记录，给出新的 reviewed_on 或 next_review_at，把状态调整回 featured／catalog，再重新生成。新增精选超出上限时生成失败，要求先合并或移出旧项，不自动截断隐藏超额项。

## 维护命令

```bash
python3 scripts/refresh_signals.py
python3 scripts/update.py --offline
python3 scripts/validate.py
python3 -m unittest discover -s tests -v
python3 scripts/build_pages.py
```

离线更新使用已缓存的技能固定版本；Star 刷新是可选联网步骤。当前不删除原始索引中的归档条目。上游精选 ID 消失时列入 `data/lifecycle-report.json` 的 missing_featured，维护者需核对迁移或替代来源。
